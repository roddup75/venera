\begin{abstract}
This document defines two complementary implementations of the methodology for estimating the capacity of a long-only equity
strategy. It separates the methodology from portfolio-specific runs. Each run should produce a
separate report containing the supplied inputs, fitted parameters, diagnostics, scenarios,
thresholds and warnings. Appendices A--C define the user input contract and distinguish supplied,
policy and fitted parameters.
\end{abstract}

\section{Framework overview}
The framework maps assets under management (AUM) into a distribution of parent-order
participation, execution horizons, implementation costs and captured alpha:
\begin{equation}\label{eq:flow}
 A\rightarrow F_A(p)\rightarrow D(p)\rightarrow
 \{\bar c(A),R_g(A)\}\rightarrow R_{\mathrm{net}}(A),IR_{\mathrm{net}}(A).
\end{equation}
Turnover $T$ is one-way annual turnover, so purchases and sales are approximated by $2TA$. In the ADV branch this is intended trading before an execution-horizon constraint. Observed cost is expressed in basis points per executed notional; the ADV scenario cost below includes completion and is expressed per intended traded dollar.

The model consumes either aggregate ADV buckets or, preferably, parent-order data. In the Burr implementation, aggregate bucket shares are shares of executed notional. The ADV-calibrated implementation jointly fits parent-order counts and traded values, using universe ADV percentiles as a liquidity prior. These are distinct weighting measures and are reported separately.

\section{Strategy economics}
At current AUM $A_0$, the key quantities are gross relative return $R_g$, tracking error $TE$,
turnover $T$ and average holdings $N$:
\begin{equation}\label{eq:economics}
 IR_g=\frac{R_g}{TE},\qquad
 \alpha_{\mathrm{holding}}=\frac{R_g}{N},\qquad
 \alpha_{\mathrm{cycle}}=\frac{R_g}{T},\qquad
 \mathcal{H}\approx\frac{1}{T}.
\end{equation}
Here $\mathcal{H}$ denotes the approximate holding period in years; $H$ below denotes the number of holdings. Current gross alpha is treated as already reflecting the current implementation schedule. Alpha
decay at alternative AUM levels is therefore measured relative to the current schedule.

\section{Distributional liquidity migration}\label{sec:migration}
Capacity depends on parent-order participation $p=Q/\mathrm{ADV}$, not ADV in isolation. Modelling
ADV alone would require a joint model for parent-order size and its dependence on ADV.

\subsection{Burr reference model}
The aggregate implementation fits a Burr XII distribution:
\begin{equation}\label{eq:burr}
 F(p;c,d,\lambda)=1-\left[1+\left(\frac{p}{\lambda}\right)^c\right]^{-d}.
\end{equation}
It offers a flexible body and Pareto-like survival tail $1-F(p)\sim p^{-cd}$. Empirical work finds
power-law tails in trade-size distributions \cite{rak2007}. The calibration constrains $cd\geq
1.25$, preserving a heavy tail while ensuring finite mean participation.

The distribution changes with AUM through
\begin{equation}\label{eq:scaling}
 \lambda(A)=\lambda_0\left(\frac{A}{A_0}\right)^\eta,
 \qquad
 d(A)=d_0\left(\frac{A}{A_0}\right)^{-\kappa}.
\end{equation}
The scale elasticity $\eta$ captures how participation grows with AUM. Tail drift $\kappa$ is
reserved for structural changes in liquidity composition. Bucket shares follow smoothly from
\begin{equation}\label{eq:weights}
 w_i(A)=F_A(u_i)-F_A(\ell_i).
\end{equation}


The participation distribution enters the capacity calculation through its quantile representation.
The distribution is weighted by executed notional: each equal-width quantile interval represents an equal fraction of
traded value, not an equal number of trades. At each AUM, set
$F_A(p)=F(p;c,d(A),\lambda(A))$. Its inverse turns a fixed rank $q\in(0,1)$ into participation:
\begin{equation}\label{eq:quantile}
 p_A(q)=F_A^{-1}(q)
 =\lambda(A)\left[(1-q)^{-1/d(A)}-1\right]^{1/c}.
\end{equation}
The same rank is used at current and alternative AUM. This is a rank-preserving scenario
assumption, not an observation that the same individual orders recur. It supplies the paired
participations needed for the horizon ratio in equation~\eqref{eq:effective}. When $\kappa=0$,
$p_A(q)=p_{A_0}(q)(A/A_0)^\eta$; with tail drift, the full inverse in
equation~\eqref{eq:quantile} is required.

Bucket weights in equation~\eqref{eq:weights} summarize this distribution for charts. The
continuous model does not multiply them into its costs a second time: the notional weights
are already represented by the quantile average made explicit in Section~\ref{sec:net}.


\subsection{Joint ADV and parent-order calibration}\label{sec:joint}
Let $n_b$ and $V_b$ be the annual parent-order count and traded dollars in participation bucket
$b=(\ell_b,u_b]$. Let $A_\star$, $H_\star$ and $T_\star$ denote the fixed historical AUM,
average holdings and one-way turnover. These historical quantities are distinct from editable
scenario inputs. The sample determines
\begin{equation}\label{eq:historical}
 N_\star=\sum_b n_b,\qquad V_\star=\sum_b V_b,\qquad
 T_\star=\frac{V_\star}{2A_\star},\qquad \bar Q_b=\frac{V_b}{n_b}.
\end{equation}
Universe ADV quantiles describe the cross-section of eligible stocks, not the frequency or value
of trades. For supplied percentile fractions $r_j$ and dollar ADVs $L_j$, interpolate between
successive points in log dollars:
\begin{equation}\label{eq:advinterpolation}
 L(r)=\exp\{(1-t)\log L_j+t\log L_{j+1}\},\qquad
 t=\frac{r-r_j}{r_{j+1}-r_j}.
\end{equation}
The current quadrature uses 100 midpoint percentile ranks and 16 evenly spaced interior
participation points within each bucket. A candidate cell $k$ in bucket $b$ has ADV $L_k$,
participation $p_k\in(\ell_b,u_b)$ and ticket $Q_k=p_kL_k$.
Its positive prior weight is proportional to
\begin{equation}\label{eq:prior}
 \pi_{bk}\propto\exp\left\{\beta(2r_k-1)
 -\frac12\left[\frac{\log(Q_k/\bar Q_b)}{1.5}\right]^2\right\}.
\end{equation}
The fixed log-ticket width 1.5 is a modelling choice. The liquidity-preference parameter
$\beta\in\{-2,0,2\}$ favours illiquid, neutral or liquid ranks before calibration.
For each bucket, minimum-relative-entropy weights satisfy
\begin{equation}\label{eq:jointfit}
 \min_{w_{bk}\geq0}\sum_k w_{bk}\log\frac{w_{bk}}{\pi_{bk}},
 \qquad \sum_k w_{bk}=1,\qquad \sum_k w_{bk}Q_k=\bar Q_b.
\end{equation}
The implementation solves the one-dimensional exponential tilt
\begin{equation}\label{eq:tilt}
 w_{bk}(\theta_b)=\frac{\pi_{bk}\exp(\theta_b Q_k/Q_{b,\max})}
 {\sum_h\pi_{bh}\exp(\theta_b Q_h/Q_{b,\max})},\qquad
 \nu_{bk}=n_bw_{bk}.
\end{equation}
Thus $\sum_k\nu_{bk}=n_b$ and $\sum_k\nu_{bk}Q_k=V_b$. Fractional counts are quadrature
weights, not claims that fractional historical orders occurred. A bucket whose mean ticket lies
outside the candidate support is reported as infeasible. Changing preference refits the weights.
The observations do not uniquely identify the joint distribution: the prior resolves an
underidentified allocation. It does not impose equal trading shares across universe deciles or
reconstruct the actual 40-stock portfolio.

\subsection{Scenario scaling and migration}\label{sec:advscaling}
For scenario AUM $A$, holdings $H$ and decimal one-way turnover $T$, the ADV model uses
\begin{equation}\label{eq:advscaling}
 s_Q=\frac{A}{A_\star}\frac{H_\star}{H},\qquad
 s_N=\frac{H}{H_\star}\frac{T}{T_\star},\qquad
 Q'_k=s_QQ_k,\quad \nu'_k=s_N\nu_k,\quad p'_k=\frac{Q'_k}{vL_k}.
\end{equation}
Here $v>0$ is the market-volume factor (1 for observed ADV, 0.5 for a 50\% volume stress).
Higher turnover increases frequency, rather than ticket size, under this convention.
Higher holdings decreases tickets and increases frequency. These behavioural assumptions imply
\begin{equation}\label{eq:conservation}
 \sum_k\nu'_kQ'_k=s_Ns_QV_\star=2AT.
\end{equation}
For positive turnover, count and intended-notional migration shares are
\begin{equation}\label{eq:advmigration}
 f_b(A)=\frac{\sum_k\nu'_k\mathbf{1}_{\{p'_k\in b\}}}{\sum_k\nu'_k},\qquad
 w_b(A)=\frac{\sum_k\nu'_kQ'_k\mathbf{1}_{\{p'_k\in b\}}}{\sum_k\nu'_kQ'_k}.
\end{equation}
At zero turnover the interface displays zero trading shares. It continues to show hypothetical
order-level execution diagnostics. An additional bucket retains participation above 100\% ADV.
The ADV engine does not apply Burr elasticities $\eta$ or $\kappa$; one annual sample cannot
identify their response to AUM growth. Frequency changes alone leave percentage migration unchanged.

\section{Impact model}
Expected and realised costs are fitted separately using
\begin{equation}\label{eq:impact}
 c(p)=a+bp^\gamma,
\end{equation}
subject to positive parameter bounds. Square-root impact is an important benchmark, while the
implementation permits the exponent to be fitted \cite{farmer2011}. At current AUM, the continuous
distributional expectation is calibrated back to the observed notional-weighted bucket cost.

\section{Execution horizon}
In the Burr reference model, for target daily participation $\rho$ and maximum horizon $D_{\max}$,
\begin{equation}\label{eq:days}
 D(p)=\min\!\left(D_{\max},\max\!\left(1,
 \left\lceil\frac{p}{\rho}\right\rceil\right)\right).
\end{equation}
Current costs already embed the current schedule, so counterfactual effective participation is
\begin{equation}\label{eq:effective}
 p_{\mathrm{eff},j}(A)=p_j(A)\frac{D_j(A_0)}{D_j(A)}.
\end{equation}
The rule exposes the cost-versus-delay trade-off studied in optimal execution
\cite{almgren2001}. A production version can replace it with direct optimisation.


In the ADV-calibrated model, the participation limit is enforced without treating truncated
orders as complete. Required days, scheduled days and completion fraction are
\begin{equation}\label{eq:advexecution}
 D_k^{\rm req}=\max(1,\lceil p'_k/\rho\rceil),\qquad
 d_k=\min(D_{\max},D_k^{\rm req}),\qquad
 e_k=\min(1,D_{\max}\rho/p'_k).
\end{equation}
The implementation floors $D_{\max}$ to a positive integer. Required-day averages use
$D_k^{\rm req}$, not $d_k$. Impact uses $\widetilde p_k=\min(p'_k,\rho)$ as a daily-rate proxy.
This proxy approximates a participation-capped schedule and does not model the smaller final
slice separately. Alpha capture uses equal slices over $d_k$ for the completed fraction.
These two scheduling approximations should be refined together when daily executions are available.

\section{Alpha decay}
Let $H_\alpha$ be signal half-life in trading days and $\delta=\log(2)/H_\alpha$. For equal daily
slices over $D$ days, average alpha capture is
\begin{equation}\label{eq:capture}
 g(D,H_\alpha)=\frac{1}{D}\sum_{t=0}^{D-1}e^{-\delta t}
 =\frac{1-e^{-\delta D}}{D(1-e^{-\delta})}.
\end{equation}
For the Burr model, normalising each notional rank to current implementation gives
\begin{equation}\label{eq:gross}
 R_g(A)=R_g(A_0)\,
 \mathbb{E}\left[\frac{g(D_j(A),H_{\alpha,j})}
 {g(D_j(A_0),H_{\alpha,j})}\right].
\end{equation}
Aggregate runs currently weight alpha by executed notional. Trade-level runs should weight by each
order's forecast alpha contribution. Predictors with different mean-reversion speeds imply
different desired trading speeds \cite{garleanu2013}.


For the ADV model, the completed alpha fraction is $e_k g(d_k,H_\alpha)$; unfinished notional
contributes zero captured alpha. The engine normalises the aggregate capture to its historical
aggregate, rather than averaging the individual ratios used by Burr. The resulting equation is
specified below.

\section{Net capacity}\label{sec:net}
\subsection{Burr implementation}
The participation distribution specified in Section~\ref{sec:migration} determines $p_A(q)$
through equations~\eqref{eq:burr}, \eqref{eq:scaling} and \eqref{eq:quantile}.
For each notional rank $q$, the execution rule in equation~\eqref{eq:days} is evaluated
at current and alternative AUM:
\begin{equation}\label{eq:paired}
 \begin{aligned}
 D_A(q)&=D\!\left(p_A(q)\right),\qquad D_0(q)=D\!\left(p_{A_0}(q)\right),\\
 p_{\mathrm{eff},A}(q)&=p_A(q)\frac{D_0(q)}{D_A(q)}.
 \end{aligned}
\end{equation}
Thus distributional migration has two channels: it changes effective participation and
therefore impact, and it changes execution days and therefore alpha capture.

Let $\bar c_{\mathrm{obs},0}=\sum_i w_{i,0}^{\mathrm{obs}}c_i^{\mathrm{obs}}$ be the observed
current notional-weighted cost in basis points. The impact function $c(p)$ in
equation~\eqref{eq:impact} is the raw fitted curve. Its baseline calibration multiplier is
\begin{equation}\label{eq:calibration}
 K=\frac{\bar c_{\mathrm{obs},0}}
 {\displaystyle\int_0^1 c\!\left(p_{A_0}(q)\right)\,dq}.
\end{equation}
Expected and realised curves each use their own multiplier. Making the expectation explicit,
the expected cost and captured gross alpha are
\begin{equation}\label{eq:costexpectation}
 \bar c(A)=K\int_0^1 c\!\left(p_{\mathrm{eff},A}(q)\right)\,dq,
\end{equation}
\begin{equation}\label{eq:alphaexpectation}
 R_g(A)=R_g(A_0)\int_0^1
 \frac{g(D_A(q),H_\alpha)}{g(D_0(q),H_\alpha)}\,dq.
\end{equation}
Here $g$ is equation~\eqref{eq:capture}, and a common half-life is used for the aggregate
model. These integrals are the notional-weighted expectations previously written as
$\mathbb E[\cdot]$. Integrating over uniform ranks is equivalent to integrating over the
participation distribution supplied by Section 3, with current and alternative horizons
paired at the same rank.

The expectations are evaluated numerically using $J$ equally weighted midpoint quantiles:
\begin{equation}\label{eq:quadrature}
 \begin{aligned}
 q_j&=\frac{j-\tfrac12}{J},\quad j=1,\ldots,J,\qquad
 K_J=\frac{\bar c_{\mathrm{obs},0}}
 {J^{-1}\sum_{j=1}^{J}c(p_{A_0}(q_j))},\\
 \bar c_J(A)&=\frac{K_J}{J}\sum_{j=1}^{J}c(p_{\mathrm{eff},A}(q_j)),\\
 R_{g,J}(A)&=\frac{R_g(A_0)}{J}\sum_{j=1}^{J}
 \frac{g(D_A(q_j),H_\alpha)}{g(D_0(q_j),H_\alpha)}.
 \end{aligned}
\end{equation}
The factor $1/J$ supplies the notional weight. There is no additional bucket-share multiplier.
Using the same numerical grid in the calibration denominator and cost average ensures
$\bar c_J(A_0)=\bar c_{\mathrm{obs},0}$ and $R_{g,J}(A_0)=R_g(A_0)$.
The continuous impact expectation requires $c\,d(A)>\gamma$ for the Burr tail; the finite-mean
participation constraint alone does not guarantee this for every fitted exponent or AUM.
Finite-grid runs should check sensitivity to $J$, particularly under tail thickening.

The resulting impact estimate is converted from cost per executed notional into annual
cost per unit of portfolio capital using one-way turnover:
\begin{equation}\label{eq:drag}
 C(A)=\frac{2T\bar c(A)}{10{,}000}.
\end{equation}
The conversion by $10{,}000$ changes basis points into a decimal return. Net alpha and IR are
\begin{equation}\label{eq:net}
 R_{\mathrm{net}}(A)=R_g(A)-C(A),\qquad
 IR_{\mathrm{net}}(A)=\frac{R_{\mathrm{net}}(A)}{TE}.
\end{equation}
The quantities $R_g$, $C$ and $TE$ are expressed as decimal annual returns, and $T$ as
decimal one-way turnover. Distributional migration therefore affects both components of
net return: impact in $C(A)$ and delay in $R_g(A)$. Tracking error and turnover remain fixed assumptions
in this specification.

For example, consider a notional rank whose participation increases from 8\% to 16\% ADV. With a 10\% daily
target and a non-binding horizon cap, its horizon increases from one to two days.
Effective participation becomes $16\%\times1/2=8\%$, so its modeled impact is unchanged,
while its alpha-capture ratio becomes $g(2,H_\alpha)/g(1,H_\alpha)<1$.
Migration can therefore lower net IR through delay even when scheduling offsets the impact
increase. This is an illustrative rank, not a claim about the entire portfolio.

A run report should show the complete capacity curve and explicitly selected thresholds rather
than presenting a single universal capacity number.


\subsection{ADV-calibrated implementation}\label{sec:advnet}
Section~\ref{sec:joint} supplies calibrated synthetic counts and tickets. Section~\ref{sec:advscaling}
scales them into participation, and equation~\eqref{eq:advexecution} supplies completion and delay.
Because every ticket scales by the same factor, the intended-notional weights are invariant:
\begin{equation}\label{eq:advweights}
 \omega_k=\frac{\nu_kQ_k}{V_\star},\qquad \sum_k\omega_k=1.
\end{equation}
Evaluate the historical reference at $A=A_\star$, $H=H_\star$, $v=1$, under the selected daily
participation limit, horizon and half-life. Use a subscript $\star$ for those reference execution
quantities. Then
\begin{equation}\label{eq:advnormalisation}
 G_\star=\sum_k\omega_ke_{k,\star}g(d_{k,\star},H_\alpha),\qquad
 K_{\rm ADV}=\frac{\sum_b(V_b/V_\star)c_b^{\rm obs}}
 {\sum_k\omega_ke_{k,\star}c(\widetilde p_{k,\star})}.
\end{equation}
The current dashboard uses expected bucket costs for this anchor. Its captured gross alpha and
cost in basis points per intended traded dollar are
\begin{equation}\label{eq:advnetinputs}
 \begin{aligned}
 R_g^{\rm ADV}(A)&=R_{g,\star}
 \frac{\sum_k\omega_ke_kg(d_k,H_\alpha)}{G_\star},\\
 \bar c^{\rm ADV}(A)&=K_{\rm ADV}\sum_k\omega_ke_kc(\widetilde p_k),\\
 U(A)&=\sum_k\omega_k(1-e_k).
 \end{aligned}
\end{equation}
Here $U$ is the unfinished fraction of intended notional. Substituting $\bar c^{\rm ADV}$ into
equations~\eqref{eq:drag} and \eqref{eq:net} yields annual drag, net alpha and net IR. In this
branch $2AT$ is intended annual trading; completion is already included through $e_k$, and must
not be applied again. Declining costs caused by non-completion are not evidence of improved
execution: $U$ and captured alpha must be read alongside costs.

At the historical reference the normalisation reproduces the supplied alpha and weighted cost.
Changing execution-policy controls also changes $G_\star$ and $K_{\rm ADV}$. Consequently the
current engine compares relative AUM scenarios under each selected policy; it is not an absolute
historical execution-policy backtest. Neither aggregate branch identifies overlapping orders in
one stock, time-varying volume, actual holdings selection or order-level alpha contributions.

\section{Required run-report contents}
Every portfolio run report must include:
\begin{enumerate}
  \item run identity, timestamp, code version and input source;
  \item supplied strategy, liquidity, execution and alpha-decay inputs;
  \item fitted distribution and impact parameters with fit diagnostics;
  \item current-AUM reconciliation to observed costs and alpha;
  \item AUM scenario table and continuous capacity curves;
  \item engine identity, count and dollar calibration residuals, migration and execution-horizon diagnostics;
  \item for ADV runs, preference prior, volume stress, uncapped required days and unfinished notional;
  \item selected capacity thresholds and exact crossing estimates;
  \item data-quality, extrapolation and model-risk warnings.
\end{enumerate}

\section{Validation requirements}
A valid run should confirm that notional shares sum to one, AUM and half-life are positive,
participation buckets are ordered and non-overlapping, expected and realised costs share a common
benchmark, and current-AUM impact reconciles to the supplied weighted cost. The report should flag
missing trade-level alpha weights, large extrapolations, horizons at $D_{\max}$, unstable tail fits
and sensitivity to user policy parameters.

liquidity preference and ticket-prior width require sensitivity review before operational use.

\section{Running the dashboard implementations}\label{sec:running}
The methodology is distributed through two dashboard implementations. The browser version
evaluates the model interactively from the source parameters. The Power BI version uses generated
scenario tables so that it can be distributed through standard Power BI files and workspaces.
Both implementations use USD, the same live bucket observations, the same universe ADV
quantiles and the same Burr and ADV calibration inputs.

\subsection{Browser dashboard}
The browser dashboard requires Node.js 22.13 or later. From the project root, install the locked
dependencies and start the local development server with
\begin{verbatim}
cd dashboard
npm ci
npm run dev -- --host 127.0.0.1 --port 3011
\end{verbatim}
The dashboard is then available at \url{http://localhost:3011}. The process remains attached to
the terminal and is stopped with \texttt{Ctrl+C}. Before distributing a change, the production
build and the model checks should be run from the \texttt{dashboard} directory:
\begin{verbatim}
npm run build
node --experimental-strip-types --test tests/adv-migration.test.mjs
\end{verbatim}
The browser version recalculates immediately when the user changes AUM, holdings, turnover,
participation, execution horizon, alpha half-life or the available model-specific controls.

\subsection{Power BI dashboard}
\begin{sloppypar}
The portable Power BI materials are stored in the \path{powerbi} directory and in the archive
\path{CapacityLab-PowerBI.zip}. On a Windows machine with Power BI Desktop, the archive is
extracted and every CSV file in \texttt{powerbi/data} is imported through \emph{Get data--Text/CSV}.
The first row is promoted to column headers. The measures in
\path{powerbi/CapacityLab.dax} are added to the \texttt{Scenarios} table, and
\path{powerbi/CapacityLab-theme.json} is imported through
\emph{View--Themes--Browse for themes}. The accompanying README specifies the fields and visual
types for the Overview, Liquidity migration and Demo building blocks pages. The completed report
can be saved as a \texttt{.pbix} file or as a source-controlled \texttt{.pbip} project.

The supplied Power BI tables cover AUM from \$0.1bn to \$15.0bn in \$0.1bn increments. They
include the ADV-calibrated and Burr scenarios, traded-dollar and parent-order migration,
execution outcomes, alpha-decay paths, bucket inputs, ADV percentiles and fitted calibrations.
After changing a structural model input, the scenario tables are regenerated from the
\texttt{dashboard} directory with
\begin{verbatim}
node --experimental-strip-types scripts/export-powerbi.mjs
\end{verbatim}
and the Power BI tables are refreshed. AUM, model and view selections operate as report filters;
turnover, holdings, participation limits and fitted coefficients require regeneration because the
Power BI implementation is a scenario grid rather than a live JavaScript calculation engine.
\end{sloppypar}

\section{Fitted parameters and outputs}
The user does not normally supply Burr parameters $(c,d,\lambda_0)$ or impact parameters
$(a,b,\gamma)$; the model estimates them. Every run report should disclose them along with the tail
index $cd$, bucket-fit residuals, impact-fit residuals, baseline calibration multiplier, threshold
crossings and warnings. Parameters should be versioned with their input sample and estimation date. ADV runs additionally disclose bucket tilts, grid density, prior width, preference, count and value residuals, and the distinction between exact historical turnover and rounded scenario inputs.
